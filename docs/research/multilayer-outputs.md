## Answer in brief

- **The first inner copper Layer is physical `L2`.** KiCad calls it `In1.Cu` and writes `Copper,L2,Inr`. Its writer deliberately omits the optional copper type. A filename ending in `.g1` can therefore describe the same physical position as a fab’s `.G2L`. The leading suite also has separate numbering sequences for inner signal and plane artwork. [KiCad Gerber writer][kcopper], [OSH Park naming examples][osname], [the leading suite’s extension guide](https://valhalla.altium.com/Learning-Guides/OG0101%20Gerber%20Output%20Options.pdf)
- **A drill file describes an operation over a copper span.** Gerber separates spans and plating. KiCad names ordinary partial-span files by their two Layer names. The leading suite also separates laser micro Via drill pairs. A back-drill is a second operation on an existing plated barrel and can legitimately appear as `NonPlated,…,Blind`. [Gerber §6.6][gerber], [KiCad drill writer][kdrill], [the leading suite’s micro Via documentation](https://www.altium.com/documentation/altium-designer/pcb/blind-buried-micro-vias)
- **The copper file list and the material Stackup answer different questions.** `FilesAttributes` identifies which image occupies `L2`. `MaterialStackup` describes what lies above and below that copper. If supplied, the array must include every material entry in physical order. `Type` alone is sufficient for an entry whose properties are unspecified. KiCad writes this array. The leading suite documents separate spreadsheet and drawing exports. [Job §§2.5, 2.7][job], [schema][schema], [KiCad job writer][kjob], [the leading suite’s Stackup documentation](https://www.altium.com/documentation/altium-designer/pcb/defining-layer-stack)
- **The documented prototype path at four to six Layers is all copper images, the board profile, mask and legend as used, and through-drill data.** OSH Park and AISLER exclude blind and buried Vias from the cited services. JLCPCB and PCBWay offer them through HDI processes with separate quoting or additional fabrication cost. JLCPCB’s HDI service explicitly asks for both endpoints in each partial-span drill filename. [OSH Park][os6], [AISLER][ar6], [JLCPCB standard upload][jplot], [JLCPCB HDI][jhdi], [PCBWay][pvia]

## 1. Inner copper filenames, X2 functions, and plane polarity

| Source | What identifies an inner Layer |
|---|---|
| Gerber | §3.6 gives `.gbr` or `.GBR` as the standard extension. In §5.6.3 the physical copper positions run consecutively from the top. On a six-Layer board the inner functions run from `Copper,L2,Inr` through `Copper,L5,Inr`. An optional fourth field is `Plane`, `Signal`, `Mixed`, or `Hatched`. §5.6.4 gives a **positive** inner `Plane` example. `FilePolarity` separately states whether the image depicts material present or absent. Ucamco recommends positive copper. [Gerber §§3.6, 5.6.3–5.6.4][gerber] |
| The leading suite | The X2 dialog offers an editable, underscore-separated name with `.gbr`, or a common board name with Layer-specific extensions. A publisher example calls two inner files `DB31_Copper_Signal_1.gbr` and `DB31_Copper_Plane_1.gbr`. In classic naming, `.G1`, `.G2`, … enumerate mid-signal Layers and `.GP1`, `.GP2`, … enumerate internal planes. Thus `.G1` and `.GP1` can coexist. The X2 exporter includes Layer-function information. Its documentation does not establish the literal optional type field for every inner-Layer case. [Fabrication settings](https://www.altium.com/documentation/altium-designer/preparing-for-manufacture/output-jobs/fabrication-data), [X2 example](https://files.resources.altium.com/sites/default/files/uberflip_docs/file_1156.pdf), [extension guide](https://valhalla.altium.com/Learning-Guides/OG0101%20Gerber%20Output%20Options.pdf) |
| KiCad | With standard Layer names and the `.gbr` naming option, the plotter turns `In1.Cu` into `<board>-In1_Cu.gbr`. The Protel option changes the first inner extension to `.g1`, the second to `.g2`, and so on. The X2 writer emits `Copper,L2,Inr` for the first inner Layer and marks copper positive. The code for appending a routing or plane type is disabled. A filled ground Zone therefore needs no special plane extension or type suffix. [Filename construction][knames], [Gerber writer][kcopper], [fab’s worked KiCad example][jplot] |
| A second commercial suite | The PCB Editor tutorial generates artwork films from the cross-section. Film records control each output name and its included classes. The tutorial shows `.art` files. The suite’s six-Layer example configures films and subclasses, and its guide lists `.IN1`, `.IN2`, `.PWR`, and `.GND` as common exchange names. Those examples do not establish universal default extensions or X2 header values. [PCB Editor tutorial, pp. 76–77](https://www.cadence.com/content/dam/cadence-www/global/en_US/documents/solutions/cadence-cloud/oncloud/orcad-tutorial.pdf#page=76), [film configuration](https://resources.academic.cadence.com/pcb-design-and-analysis-resources/2024-how-to-generate-gerber-files-in-orcad-x-cadence) |
| Horizon EDA | The fabrication dialog concatenates a base filename with the configured Layer suffix. The manual describes RS-274X artwork and NC drills. The project describes rendering plane fragments with dark and clear Gerber regions. These are operations within the image. Neither source establishes a negative whole-file plane convention or an emitted X2 copper type. [Fabrication dialog, §2.12][hmanual], [plane export notes][hspan] |

The practical ambiguity is visible at intake. OSH Park reports four-Layer uploads where `.GP1` and `.G1` both appear to mean “first inner.” Its recovery names are `.G2L` and `.G3L` in physical order, and it asks for positive inner artwork. JLCPCB’s naming page also recognizes `.G1` and `.G2` but warns that it does not look for the commonly negative `.GP1` and `.GP2`. Renaming resolves an identification problem. It does not change the image polarity. [OSH Park naming][osname], [OSH Park inner-plane polarity][os4], [JLCPCB naming][jnames], [Gerber §5.6.4][gerber]

## 2. Drill files per Via span

For a six-Layer board, these are three distinct plated drill sets. The KiCad filenames and header comments below are worked examples derived from its published writer with the full Excellon header enabled. In particular, `in1` in a filename becomes `2` in the header because the header counts physical copper Layers. [KiCad filename and attribute builder][kdrill], [KiCad Excellon writer][knc], [XNC §§4.1–4.2][xnc]

| Holes on the board | KiCad Excellon filename | File-function comment |
|---|---|---|
| Through Vias and other plated through-holes | `radio-PTH.drl` | `; #@! TF.FileFunction,Plated,1,6,PTH` |
| Blind Vias from top to first inner | `radio-front-in1.drl` | `; #@! TF.FileFunction,Plated,1,2,Blind` |
| Buried Vias from first to second inner | `radio-in1-in2.drl` | `; #@! TF.FileFunction,Plated,2,3,Buried` |

| Source | How the span or process reaches CAM |
|---|---|
| Gerber and XNC | Gerber puts the endpoints and hole class in the file header, for example `%TF.FileFunction,Plated,2,3,Buried,Drill*%`. Endpoint order is insignificant. `Drill`, `Rout`, or `Mixed` is an optional final label. `Microvia` is not a separate file-function class. XNC carries the corresponding file attribute in a structured comment. An NC reader can plot the coordinates while ignoring that comment and losing the span. [Gerber §5.6.3][gerber], [XNC §4.1][xnc] |
| The leading suite | NC output creates a file for each drill pair. Its ASCII family starts with `.TXT` and can use distinct extensions for additional files. The `.LDP` report identifies drill pairs to the CAM editor, and `.DRR` identifies files and tools. Micro Vias get a separate NC file for each laser drill pair and separate X2 plot entries. For back-drilling, the documented X2 example names both endpoints in `<design>_Backdrills_Drill_1_3.gbr` and writes `NonPlated,1,3,Blind,Drill`. The NC example uses `-BackDrill.TX3` and `-BackDrill.TX4` for two operations. The extension number in that example is not a physical Layer number. [NC output documentation](https://www.altium.com/documentation/altium-designer/preparing-for-manufacture/output-jobs/fabrication-data), [micro Via outputs](https://www.altium.com/documentation/altium-designer/pcb/blind-buried-micro-vias), [back-drill examples](https://www.altium.com/documentation/altium-designer/pcb/high-speed-design/configuring-stackup-controlled-depth-drilling-back-drilling) |
| KiCad | The writer groups ordinary Vias by unique copper pair. A micro Via and another plated Via on the same pair share that grouping. Back-drills are enumerated separately. The full Excellon header uses numeric endpoints and omits the optional drill/rout label. The minimal-header option suppresses the file-function comment. The Gerber drill writer uses an X2 attribute and adds `-drl` to ordinary drill plot names. [Span enumeration][kspans], [attribute construction][kdrill], [Excellon writer][knc], [Gerber drill writer][kgdrill] |
| A second commercial suite | The NC setup offers Layer-pair and by-Layer modes. Its documented back-drill example separates files by side and depth. A suffix such as `-bd-10-9.drl` identifies the operation, and human-readable header comments name the start and end Layers, the Layer that must remain intact, and the maximum drill depth. That evidence is specific to back-drilling. [NC setup, fig. 5-17](https://www.cadence.com/content/dam/cadence-www/global/en_US/documents/solutions/cadence-cloud/oncloud/orcad-tutorial.pdf#page=79), [back-drill handoff](https://www.cadence.com/content/dam/cadence-www/global/en_US/documents/tools/pcb-design-analysis/pcb-west-2016-40-managing-backdrill-cp.pdf) |
| Horizon EDA | The Gerber package has an individual drill output for every used span. The user assigns a filename suffix to each span. Its ODB++ export instead records the drill span in the job metadata. [Via documentation][hvias], [implementation notes][hspan] |

## 3. Plated and non-plated splits per span

**An NPTH mounting hole and a non-plated partial-span operation describe different work.** Ucamco’s eight-Layer example first drills a plated Via through `1,8`. A second file, `NonPlated,8,7,Blind`, describes removal of plating at the bottom end of that barrel. Its tool function is `BackDrill`. The generic grammar also permits `NonPlated,i,j,Buried`. The sources give a concrete blind back-drill example, not an ordinary buried mounting-hole example. [Gerber §§5.6.3, 5.6.10, 6.6][gerber]

| Source | Plating behavior |
|---|---|
| Gerber and XNC | Gerber requires separate drill spans and separate plated and non-plated data. XNC likewise assigns plating at file level. Neither requires a non-plated companion for a blind Via span containing only plated holes. A Gerber `Mixed` final label means drilling and routing occur in the file. It does not mean mixed plating. [Gerber §§5.6.3, 6.6][gerber], [XNC §4.1][xnc] |
| The leading suite | The NC exporter can split plated and non-plated events, marking names with `-Plated` or `-NonPlated`. Hole shape can create additional files. Back-drills always get their own files. A board can therefore produce several files for a single pair, while keeping plated blind and buried drill sets separate from through-holes. [Fabrication outputs](https://www.altium.com/documentation/altium-designer/preparing-for-manufacture/output-jobs/fabrication-data), [back-drill output rules](https://www.altium.com/documentation/altium-designer/pcb/high-speed-design/configuring-stackup-controlled-depth-drilling-back-drilling) |
| KiCad | Default Excellon output separates through PTH and NPTH. The ordinary NPTH pass covers top to bottom. The merge option combines those two through sets in `<board>.drl` with `MixedPlating,1,N`, where `N` is the copper count. Partial-span plated Via sets remain separate. Back-drilling has its own non-plated treatment. Gerber drill output keeps PTH and NPTH separate. [PCB Editor manual][kmanual], [Excellon writer][knc], [Gerber drill writer][kgdrill], [attribute builder][kdrill] |
| A second commercial suite and Horizon EDA | The former’s NC dialog has a separate-files option for plated and non-plated holes. Horizon EDA’s documented setup shows a merged PTH/NPTH `.txt` file. Its later per-span export documentation does not establish a general non-plated split for every partial span. [NC setup, fig. 5-17](https://www.cadence.com/content/dam/cadence-www/global/en_US/documents/solutions/cadence-cloud/oncloud/orcad-tutorial.pdf#page=79), [Horizon EDA §2.12][hmanual], [Horizon EDA Via outputs][hvias] |

## 4. The Stackup in the Gerber job file

| Job data | Meaning |
|---|---|
| `GeneralSpecs.LayerNumber`, `Size`, `BoardThickness` | `LayerNumber` counts copper Layers only. §3.1 calls for CAD to supply size and copper count. `BoardThickness`, when supplied, measures the base material and deposited conductive material in millimetres. `IPC-2221-Type` can identify a board class that uses blind or buried Vias. It does not enumerate their endpoints. [Job §§2.2, 2.4, 3.1][job] |
| `MaterialStackup` | The array is optional. If present, it contains all and only the board’s material entries, in physical order. A top-only legend appears once. Mask on both sides appears twice. Copper entries appear in sequence with the intervening dielectrics. One dielectric entry can represent several production prepreg plies. The array describes the design Stackup without prescribing the fab’s layup process. [Job §2.5, pp. 11–13][job] |
| Required and optional entry fields | Only `Type` is required per entry. The specification names `Copper`, `Dielectric`, `Legend`, `SolderMask`, `CoverLay`, `PeelableMask`, and `Carbon`, and allows other strings. `Material` is optional. `Thickness` is base thickness in millimetres, excluding added plating. Other optional fields include `DielectricConstant`, `LossTangent`, `Conductivity`, `Tg`, `Color`, `Name`, and `Note`. `Substacks` identifies applicable rigid-flex substacks. The schema types the physical quantities as numbers. [Job §2.5][job], [schema, `MaterialStackup.items`][schema] |
| `FilesAttributes` | Each file entry requires `Path`, relative to the job file. `FileFunction` identifies the image or drill span. `FilePolarity` and `FileFormat` can also be supplied. This array permits any file order. The second copper *material entry* and `Copper,L2,Inr` describe the same physical position through ordering and function. A dielectric needs no Gerber image or filename. [Job §§2.5, 2.7–2.8][job], [schema, `FilesAttributes.items`][schema] |
| Legacy mixed drill data | §2.7 reserves `XPlated,i,j,XTH` for identifying legacy mixed-plating data **in the job file**. This differs from KiCad’s `MixedPlating,1,N` Excellon comment. Neither spelling is a standard Gerber image-file plating function. [Job §2.7, p. 16][job], [Gerber §5.6.3][gerber], [KiCad attribute builder][kdrill] |

**KiCad** offers a Gerber job-file checkbox. Its plotter produces `<board>-job.gbrjob` and passes its plotted Gerbers to the job writer. The writer records copper count, board thickness, available finish information, file functions and polarities, and an ordered `MaterialStackup`. It handles copper, dielectric sublayers, mask, legend, and `SolderPaste` entries where present. It can write material, color, and thickness. Dielectric constant and loss tangent are conditional on the material data and dielectric constraints. Dielectric names identify bounding copper Layers, with a sublayer index where applicable. These names describe insulation between Layers, not drilled spans. [KiCad manual][kmanual], [plotter][knames], [job writer][kjob]

**The leading suite** documents a Board Stack Report in `.xls` containing Layer names, materials, thicknesses, dielectric constants, and stack heights. The Stackup editor also exports CSV. Neither output establishes that its Gerber generator writes a Ucamco `.gbrjob` or `MaterialStackup`. The sources reviewed likewise did not establish such an export for a second commercial suite or Horizon EDA. [Board Stack Report](https://www.altium.com/documentation/altium-designer/preparing-for-manufacture/output-jobs/fabrication-data), [Stackup export](https://www.altium.com/documentation/altium-designer/pcb/defining-layer-stack), [a second commercial suite’s manufacturing tutorial](https://www.cadence.com/content/dam/cadence-www/global/en_US/documents/solutions/cadence-cloud/oncloud/orcad-tutorial.pdf#page=76), [Horizon EDA fabrication outputs][hmanual]

## 5. Drill maps, drill tables, and Stackup tables on fab drawings

| Source | What a person at the fab can read |
|---|---|
| Gerber | §5.6.3 distinguishes `Drillmap`, which locates holes and can identify sizes, tolerances, and plating, from `FabricationDrawing`, which can include the profile, dimensions, Stackup, materials, and finish. Both are drawing functions. The drill/rout file carries the actual hole geometry and span. [Gerber §§5.6.3, 6.6][gerber] |
| The leading suite | The drill drawing marks hole sites with symbols. A drill table can show one Layer pair, several separate pair tables, or one composite table. Size, plating, and count can be associated with symbols. A PCB Layer Stack Table includes Layer number, name, material, thickness, dielectric constant, and Gerber identifier. A separate Layer Stack Legend draws an enlarged section and can show relative thickness and Via drill pairs, including back-drills. Classic drill drawings use `.GD1`, `.GD2`, … and guides use `.GG1`, `.GG2`, … in drill-pair order. [Drill-table settings](https://www.altium.com/documentation/altium-designer/pcb/including-design-details), [Stackup table](https://www.altium.com/documentation/altium-designer/pcb/defining-layer-stack), [section and drill views](https://www.altium.com/documentation/altium-designer/draftsman/views/additional), [classic extensions](https://valhalla.altium.com/Learning-Guides/OG0101%20Gerber%20Output%20Options.pdf) |
| KiCad | The optional map plots drill locations with tool symbols and a legend for the drill set. Maps use the drill-set name plus `-drl_map` and can be Gerber X2, PDF, SVG, DXF, or PostScript. A single text report can summarize several drill files by pair. **Add Stackup Table** places a table on a graphic Layer. Its columns include Layer name, type, material, thickness, color, relative permittivity, and loss tangent. [PCB Editor manual][kmanual], [map and report writer][kdrill], [table generator][ktable] |
| A second commercial suite | Its back-drill example shows a drawing legend identifying the drilling side, actual diameter, depth, protected Layer, and permitted stub. A separate cross-section chart draws the spans alongside the material Stackup and total thickness. This conveys a machining constraint that a pair of copper numbers alone cannot express. [Documented manufacturing handoff](https://www.cadence.com/content/dam/cadence-www/global/en_US/documents/tools/pcb-design-analysis/pcb-west-2016-40-managing-backdrill-cp.pdf) |
| Fab intake | JLCPCB explicitly encourages a drill map or drill drawing so it can check positions, attributes, and quantities. Its fabrication package still calls for the drill file. AISLER asks that the outline file contain only the outline, so a Stackup table or drill legend does not belong in that upload Layer. [JLCPCB file preparation][jprep], [AISLER upload instructions][aupload] |

## 6. Layer-order markers in copper

- **An etched number identifies a particular copper image.** The leading suite’s fabrication guide illustrates one number per Layer, inside the finished outline near an edge. The numbers are offset in plan view so that they do not obscure one another. Clearances in surrounding copper, mask, and legend allow inspection against a light. KiCad permits text directly on a copper Layer and fills Zones around it, which provides a documented way to draw such a mark manually. [The leading suite’s marking guide, p. 2](https://files.resources.altium.com/sites/default/files/uberflip_docs/file_1216.pdf#page=2), [KiCad PCB Editor manual][kmanual]
- **Stacking stripes reveal the sequence at the routed edge.** Copper strips on successive Layers occupy offset positions and cross the profile. Routing exposes their ends, making the sequence visible from the side. The leading suite’s guide distinguishes these stripes from nearby test Tracks intended for measurement. Its Layer Stack Legend is a drawing object and serves a different inspection step. [The leading suite’s marking guide, p. 3](https://files.resources.altium.com/sites/default/files/uberflip_docs/file_1216.pdf#page=3), [Layer Stack Legend documentation](https://www.altium.com/documentation/altium-designer/draftsman/views/additional)
- **One fab explicitly asks for physical labels.** PCBWay’s orientation guide asks for etched Layer labels and describes top and mirrored bottom markings for visual inspection. Its order instructions separately ask for filenames in physical order. The guide does not establish a mandatory staircase pattern. Eurocircuits documents adding coupons to its production panel and using a coupon to verify inner-Layer registration. Gerber can identify a separately described coupon with `.Part,Coupon`. [PCBWay orientation][pmark], [PCBWay order instructions][porder], [Eurocircuits panel preparation][epanel], [Eurocircuits inspection][einspect], [Gerber §5.6.2][gerber]

It also identifies the mask, legend, and outline files. [Gerber upload instructions][aupload] | AISLER publishes four- and six-Layer Stackups, with special material or Stackup requests directed to its team. The cited 35 µm ENIG rules for both Layer counts exclude blind, buried, and micro Vias. [Four-Layer Stackup][as4], [six-Layer Stackup][as6], [four-Layer rules][ar4], [six-Layer rules][ar6] |

## Differences

- **Filename numbers count different things.** For the first inner copper image, KiCad’s `In1` and `.g1` count inner Layers, X2 `L2` counts all copper Layers, and OSH Park’s `.G2L` follows physical position. The leading suite’s classic `.GP1` counts only internal planes. These distinctions matter even on a four-Layer board. [KiCad writer][kcopper], [OSH Park naming][osname], [the leading suite’s extension guide](https://valhalla.altium.com/Learning-Guides/OG0101%20Gerber%20Output%20Options.pdf)
- **A span is the minimum separation, not a universal file count.** The leading suite separates laser micro Via operations and can subdivide by hole shape. KiCad groups ordinary Vias on the same pair. Conversely, NC exporters can combine through-hole plating classes that Gerber and XNC separate. [The leading suite’s Via outputs](https://www.altium.com/documentation/altium-designer/pcb/blind-buried-micro-vias), [KiCad span enumeration][kspans], [XNC §4.1][xnc]
- **A complete material sequence can have sparse properties.** The Job specification requires completeness of the entries, while the schema requires only `Type` within each entry. Unknown dielectric material, thickness, or permittivity can be left unspecified. Neither a Stackup drawing nor recognition of X2 Layer functions establishes that a fab imports `MaterialStackup`. [Job §§2.1, 2.5][job], [schema][schema], [OSH Park’s description of X2 detection][os6]
- **The ordering channel matters.** PCBWay asks for physical order on the form. OSH Park can derive it from X2 or filenames. JLCPCB’s HDI service asks for endpoint-bearing filenames and an explicit reference to any agreed Stackup. The same archive can therefore carry enough information for one intake workflow and still need an order entry at another. [PCBWay][porder], [OSH Park][os6], [JLCPCB HDI][jhdi]
