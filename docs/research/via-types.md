# Via types and allowed spans in PCB editors

Sources read on 2026-11-18 for REDA ticket #321. The question is how PCB editors define a Via’s physical span, choose a Via during a Layer change, show its endpoints, and check whether the resulting structure can be fabricated.

A **routing Layer pair** identifies where a Track leaves one Layer and resumes on another. A **drill pair** identifies the two ends of a physical hole. On a six-Layer board, a Track can change from L1 to L2 using an L1–L6 through Via, an L1–L2 blind Via, or an L1–L2 laser-drilled micro Via. A buried Via has both ends on inner Layers. The routing destination alone therefore does not identify what the fab must drill. KiCad draws the same distinction in its Via propagation-delay table, where each row has signal Layers (where Tracks meet the Via) and Via Layers (the ends of the whole structure). [KiCad’s Via propagation table](https://docs.kicad.org/10.0/en/pcbnew/pcbnew.html#:~:text=Signal%20Layer%20From) · [JLCPCB’s illustrated Via definitions](https://jlcpcb.com/help/article/hdi-pcb-capabilities-faq)

## Where the permitted spans live

| Tool | What defines the span? | What defines the hole and copper? |
|---|---|---|
| The leading suite | The Stackup editor’s **Via Types** tab defines the Layer span of each permitted Via type. The page calls this the Z-plane span; it uses "drill pair" only when discussing drill outputs. Choosing first and last copper Layers derives the through, blind, or buried classification and a name such as `Blind 1:2`. A separate micro Via flag is available for particular spans. Every new board has a through span that cannot be deleted. [The leading suite’s documentation on defining Via types](https://www.altium.com/documentation/altium-designer/pcb/blind-buried-micro-vias) | The applicable **Routing Via Style** rule supplies diameter and hole size, using minimum, preferred and maximum values or enabled templates. A rule can target a particular Via type or endpoint pair. Several sizes can therefore use the same drill pair. [The leading suite’s documentation on routing rules](https://www.altium.com/documentation/altium-designer/pcb/design-rule-types/routing) |
| A second commercial suite | A **padstack** defines the physical Via. A blind or buried padstack has start and end Layers, and can carry a micro Via designation. An ordered **Via List** in a physical constraint set selects which padstacks a Net, Net Class, group, or region may use. Two Nets on the same Stackup can have different choices. [A second commercial suite’s documentation on padstacks](https://resources.academic.cadence.com/pcb-design-and-analysis-resources/2024-pcb-padstack-features-within-orcad-x) · [A second commercial suite’s constraint management guide, part 2](https://www.ema-eda.com/wp-content/uploads/2025/07/orcad-x-constraint-management-guide-part-2.pdf) · [A second commercial suite’s HDI manual, mirrored copy](https://www.scribd.com/document/765690123/high-density-interconnect-hdi) | The library padstack carries the hole and copper geometry. The constraint editor lets the designer add several padstacks to a list and reorder them by preference. [A second commercial suite’s documentation on padstack geometry](https://community.cadence.com/cfs-file/__key/communityserver-discussions-components-files/137/MakePadstackInAllegroSkill.pdf) · [A second commercial suite’s constraint management guide, part 2](https://www.ema-eda.com/wp-content/uploads/2025/07/orcad-x-constraint-management-guide-part-2.pdf) |
| KiCad 10.0 stable | **Physical Stackup** defines the copper Layers and Dielectrics. Each Via stores its own type and endpoints. The project’s named Layer-pair presets are routing shortcuts. A designer can also select a pair manually. Fabrication restrictions on endpoint combinations can be expressed in custom rules. [KiCad Board Setup](https://docs.kicad.org/10.0/en/pcbnew/pcbnew.html#:~:text=Physical%20stackup) · [KiCad Layer pairs](https://docs.kicad.org/10.0/en/pcbnew/pcbnew.html#:~:text=You%20can%20define%20the%20active%20pair) · [KiCad board file format](https://dev-docs.kicad.org/en/file-formats/sexpr-pcb/#track-via) | The router can use the active size preset or the Net Class dimensions. Via Properties also exposes the annulus, hole, type and endpoints. Its padstack modes allow common or Layer-specific geometry. Board Setup supplies board-wide manufacturing minima. [KiCad 10.0 PCB Editor manual, Via properties and constraints](https://docs.kicad.org/10.0/en/pcbnew/pcbnew.pdf) |

## How routing chooses a Via

**The leading suite.** While routing, `Ctrl+L` opens a destination-Layer list and keypad `+` or `−` steps between signal Layers. The router proposes a Via or a stack of Vias that makes the transition. It prefers ordinary micro Vias, then skip micro Vias, blind Vias and through Vias. While the Via is on the cursor, `6` cycles through feasible combinations and `8` lists them. The status display identifies each member of a proposed stack. If there is no short drill pair, the permanent through type can still make an inner-Layer connection where the rules permit it. The documentation does not specify a separate fallback when every candidate violates another constraint. [The leading suite’s documentation on interactive routing](https://www.altium.com/documentation/altium-designer/pcb/routing/interactive) · [The leading suite’s documentation on Via selection](https://www.altium.com/documentation/altium-designer/pcb/pads-vias)

**A second commercial suite.** In the current editor’s Add Connect command, `V` offers a Layer change. In Working Layer mode the designer chooses a valid destination. The classic editor documents a double-click at the insertion point. Its ordered list supplies the first Via or sequence that reaches the destination, and the popup offers alternatives. For example, listing L1–L2 and L2–L3 ahead of L1–L3 can make the two-hole path the default. A through Via earlier in the list can take precedence over all three. Working Layer mode requires listed Vias that reach the target. The precise message for an unreachable destination was not verified. [A second commercial suite’s current routing guide](https://resources.academic.cadence.com/pcb-design-and-analysis-resources/2025-getting-started-with-orcad-x) · [A second commercial suite’s HDI manual on Working Layers and ordered lists](https://www.scribd.com/document/765690123/high-density-interconnect-hdi) · [A second commercial suite’s product-team description of Via priority](https://community.cadence.com/cadence_blogs_8/b/pcb/posts/what-s-good-about-hdi-via-structures-check-out-the-spb16-2-release-and-see)

**KiCad 10.0.** The command chooses the Via family. `V` places a through Via and normally switches to the other Layer of the active pair. If the unfinished Track has a ratsnest connection to an item on another Layer, that item’s Layer takes precedence. `Ctrl+V` requests a micro Via and `Alt+Shift+V` requests a blind or buried Via. `<` opens a destination chooser for a through Via. An unlisted routing pair can be used manually, so omitting a pair from the presets does not reject the transition. Clearance can still block placement. In Shove mode the router stops when it cannot find a legal path. [KiCad Via placement and router modes](https://docs.kicad.org/10.0/en/pcbnew/pcbnew.html#:~:text=While%20routing%20tracks%2C%20switching%20layers) · [KiCad Layer-pair presets](https://docs.kicad.org/10.0/en/pcbnew/pcbnew.html#:~:text=Cycle%20Layer%20Pair%20Presets)

## How the span is shown

| Tool | On the board canvas | In the Stackup or a related view |
|---|---|---|
| The leading suite | The blind Via illustration splits the **hole** into the colours of the two endpoint Layers. The copper ring has its own display colour. Enabling **Via Span** prints Layer numbers inside Vias, including through Vias. **Via Nets** independently controls the Net name. [The leading suite’s documentation on Via colours](https://www.altium.com/documentation/altium-designer/pcb/pads-vias) · [The leading suite’s documentation on span labels](https://www.altium.com/documentation/altium-designer/pcb/your-view-of-the-board) | The Via Types view draws each span against the Stackup. A micro Via’s conical shape indicates drill direction, set by the order of its endpoints. While routing, the Properties panel shows a side view of the proposed Via or stack. [The leading suite’s documentation on the Stackup view](https://www.altium.com/documentation/altium-designer/pcb/blind-buried-micro-vias) · [The leading suite’s documentation on the routing preview](https://www.altium.com/documentation/altium-designer/pcb/pads-vias) |
| A second commercial suite | Optional numerals inside the Pad distinguish one hole from a stack with the same overall span. For example, `1:3` denotes a single blind Via and `1-3` denotes stacked Vias from L1 to L3. The documented display omits these labels on through Vias. [A second commercial suite’s HDI manual on span labels, p. 10](https://www.scribd.com/document/765690123/high-density-interconnect-hdi) | Edit Via List gives each candidate’s start and end Layers. **Show Viewer** opens a graphical view of the constraint set’s Vias. This lets the designer inspect the permitted structures even before any are placed. [A second commercial suite’s constraint manager manual, pp. 39–41](https://community.cadence.com/cfs-file/__key/telligent-evolution-components-attachments/00-27-01-00-00-96-42-32/cmug.pdf?Redirected=true) |
| KiCad 10.0 | Blind and buried Vias show two endpoint-coloured semicircles in the drill hole. The developer’s illustrated rendering note also shows the endpoint colours for micro Vias. The copper annulus follows the displayed copper Layer. [KiCad display issue with a test board](https://gitlab.com/kicad/code/kicad/-/work_items/25108) · [KiCad 10.0.6 release notes confirming the display fix](https://www.kicad.org/blog/2026/08/KiCad-10.0.6-Release/) · [KiCad developer’s illustrated rendering note](https://forum.kicad.info/t/post-v8-new-features-and-development-news/48614/50) | Physical Stackup shows the board construction. Via Properties identifies an individual Via’s endpoints, and **Board Statistics → Drill Holes** lists start Layer, stop Layer, hole type, dimensions and count for holes actually used. A numerical canvas label or an overlay of Via spans in the stable Stackup editor was not verified. [KiCad Physical Stackup](https://docs.kicad.org/10.0/en/pcbnew/pcbnew.html#:~:text=The%20Physical%20Stackup%20page) · [KiCad drill statistics](https://docs.kicad.org/10.0/en/pcbnew/pcbnew.html#:~:text=The%20Drill%20Holes%20tab) |

## Micro Via stacks and design-rule checks

**The leading suite.** The Stackup editor enables the micro Via flag for adjacent copper Layers, or for a *skip* spanning one intervening copper Layer. A skip from L1 to L3 is one drill definition. A stack from L1 to L3 can instead contain two separately selectable Vias, L1–L2 and L2–L3. The router can place the stack in one transition and move its members together. The documentation describes staggered construction as a series of laterally offset micro Vias. Automatic placement is documented for coincident stacks. [The leading suite’s documentation on micro and skip Vias](https://www.altium.com/documentation/altium-designer/pcb/blind-buried-micro-vias) · [The leading suite’s documentation on editing stacked Vias](https://www.altium.com/documentation/altium-designer/pcb/pads-vias)

The **Layer Pairs** rule compares Via types found on the board with the permitted Stackup types during interactive routing, online DRC and batch DRC. **Hole To Hole Clearance** checks hole edges and has an explicit switch permitting stacked micro Vias. Separate rules check hole diameter and minimum radial annular ring. **Max Via Stub Length** tests the unused barrel beyond the last connected Layer on scoped Nets, including holes that have not been back drilled. The documented maximum Via count applies per Net. A numerical count limit per stack and an automatic micro Via aspect-ratio check were not verified. [The leading suite’s documentation on manufacturing rules](https://www.altium.com/documentation/altium-designer/pcb/design-rule-types/manufacturing) · [The leading suite’s documentation on stub length and Via count](https://www.altium.com/documentation/altium-designer/pcb/design-rule-types/high-speed)

**A second commercial suite.** A stack comprises Vias on the same Net at the same coordinates, with successive members sharing an endpoint Layer. The editor can place the sequence together or split it later. For a staggered sequence, the designer positions successive members at an offset, subject to same-Net spacing. The micro Via designation lets spacing rules distinguish laser Vias from conventional blind or buried Vias through the core. [A second commercial suite’s HDI manual, pp. 7–12 and 19–20](https://www.scribd.com/document/765690123/high-density-interconnect-hdi)

The family’s extended manufacturing rules include a configurable **maximum stacked Via count**, Via and micro Via aspect ratios, and hole-to-Pad and hole-spacing checks by Via category. The count applies to the vertical stack itself. The aspect-ratio check uses the physical depth and finished hole diameter. These checks are documented in the extended manufacturing rules guide. Availability in every edition and a blanket adjacent-Layer restriction on every micro Via were not verified. Release documentation also identifies a regional Via List check. The specific report of an out-of-list padstack producing a switchable DRC error is a **secondary source, not verified** for the current editor. [A second commercial suite’s extended manufacturing rules guide](https://www.flowcad.de/AN/DesignTrueDFM_RulesGuide_17_2_QIR7.pdf) · [A second commercial suite’s release documentation on the Via List check](https://cadence.comtech.com.cn/uploads/file/20230612/1686536854800434.pdf) · [A second commercial suite’s user discussion of the diagnostic](https://community.cadence.com/cadence_technology_forums/pcb-design/f/pcb-design/15794/peculiar-drc-error)

**KiCad 10.0.** The stable manual describes individual Vias with a position, type and endpoints. In that model, a stack is represented by successive Via spans at the same coordinates. A stagger uses different coordinates and a connecting Track on the shared Layer. This is an inference from the documented objects. The stable manual allows inner endpoints for micro Vias. It does not document an automatic stack generator, a required adjacent pair for each micro Via, a maximum stack count, or a built-in aspect-ratio check. The separately published **development** manual does document a grouped stacked or staggered object with one micro Via per adjacent pair, along with span, depth and aspect-ratio checks. [KiCad 10.0 Via properties](https://docs.kicad.org/10.0/en/pcbnew/pcbnew.pdf) · [KiCad board file format](https://dev-docs.kicad.org/en/file-formats/sexpr-pcb/) · [KiCad development manual on micro Via stacks](https://docs.kicad.org/master/en/pcbnew/pcbnew.html#:~:text=A%20microvia%20normally%20connects)

Stable DRC exposes `Via_Type`, `Layer_Top` and `Layer_Bottom`. A custom rule can therefore reject a micro Via on a specified pair using `disallow`, or set an annular-width constraint for just one Via family. Built-in checks cover annular width, Via diameter, mechanical hole size and micro Via hole size. The hole-to-hole check requires at least one mechanically drilled hole and considers blind or buried holes when their spans share Layers. Two laser micro Vias alone do not trigger that drill-spacing test. An object on a disabled copper Layer is a separate violation. [KiCad custom rule reference](https://docs.kicad.org/10.0/en/pcbnew/pcbnew.html#:~:text=The%20first%20layer%20in%20the%20via%20stackup) · [KiCad DRC violation reference](https://docs.kicad.org/10.0/en/pcbnew/pcbnew.html#:~:text=Drilled%20hole%20too%20close%20to%20other%20hole)
